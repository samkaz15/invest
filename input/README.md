# 手入力するデータ

ここに置くのは、**人が自分の目で読んで書き写したもの**だけです。
MIOS が自動取得するデータは `data/raw/` に入り、こちらには来ません。

## なぜ手入力なのか

NFP（雇用統計）と失業率の月次コンセンサス予想は、MIOS が唯一ベンチマークを
持てていないデータです（[ADR-012](../docs/adr/ADR-012-consensus-benchmark.md)）。
ナイーブ基準に勝つのは低いハードルなので、**この2つの skill は CPI の skill より
弱い主張**のままになっています。

外為どっとコムなどの経済カレンダーには「予想」列があり、そこに答えがあります。
しかしその数値はほぼ確実にデータベンダーからライセンスを受けたもので、
ブローカーのサイトから**自動取得して公開リポジトリにコミットするのは再配布**です。
規約上も設計上も行いません。

人が自分の目で読んで書き写すのは、そのサイトの本来の使い方です。だからこの経路があります。

## consensus.csv の書き方

```
target_series_id,target_period,value,unit,observed_at,source_url,note
ser_us_nfp_level,2026-09-01,175,level_change,2026-09-25T09:00:00Z,https://example.com/calendar,ロイター調査中央値
```

| 列 | 意味 |
|---|---|
| `target_series_id` | 予測対象。`ser_us_nfp_level` / `ser_us_unemployment_rate` / `ser_us_cpi_index` / `ser_us_core_cpi_index` のいずれか |
| `target_period` | **参照期間**の月初（2026年9月分なら `2026-09-01`）。発表日ではありません |
| `value` | カレンダーに表示されている数字そのまま |
| `unit` | その数字が何を意味するか（下表） |
| `observed_at` | **あなたがそれを読んだ日時**（UTC, ISO-8601）。発表日ではありません |
| `source_url` | どこで読んだか。**必須**です |
| `note` | 任意。「ロイター調査中央値」など |

### unit の選び方 — ここを間違えると桁ごと狂います

| unit | 市場での言い方 | 書く値 | 使う対象 |
|---|---|---|---|
| `percent_change` | 「前月比 +0.3%」 | `0.3` | CPI / コアCPI |
| `level_change` | 「+17.5万人」（千人単位） | `175` | NFP |
| `level` | 「4.3%」（**水準**） | `4.3` | 失業率 |

`level` だけ特別です。失業率は**水準**で報じられますが MIOS は**変化**を予測するので、
`observed_at` 時点で知り得た前月の値との差に変換されます。
そのまま保存すると「コンセンサスは +4.3%ポイント」という、
丸め誤差ではなく**二桁違う**数字が入り、人間の予測家が壊滅的に下手に見えます。

対象の transform と unit が食い違う行は**変換せずエラーになります**。推測はしません。

### observed_at が vintage になります

10日前に書き写した予想は、発表前日に書き直しても**消えません**。
`external_forecasts` は追記のみで、DB トリガが上書きを拒否します。
だから「発表10日前のコンセンサスは何だったか」が後から再現できます。

同じ数字を再度書いても行は増えません（値が変わった時だけ記録します）。

## 取り込み

```bash
mios consensus
```

`mios daily` の中でも自動的に実行されます。

**1行でも不正なら、そのファイルは1行も取り込まれません。** 黙って行を捨てるファイルは、
読み込めないファイルより悪いからです — 記録されたと思い込んだまま、
半年後に比較に穴が空いていることに気づくことになります。

## Tier 3 であること

コンセンサスは Tier 3（報道・集計の再配信）として保存されます。
**単独で数値の根拠にはしません**（憲法第4条）。
あくまで MIOS 自身の予測を測るための比較対象であり、観測値ではありません。
