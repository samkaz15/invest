# CONSTITUTION.md
# Macro Intelligence Operating System（MIOS）憲法

> 本書はMIOSプロジェクトの最上位文書である。他のすべての設計書・実装・運用は本書に従属する。
> 本書と矛盾する実装・提案は、本書を改正しない限り無効である。
>
> 前身である BIOS（Bitcoin Intelligence OS）の憲法は `archive/docs/bios/PROJECT_CONSTITUTION.md`
> に保存されている。本書はその規律の多くを継承しつつ、目的を「売買判断」から
> 「経済指標の予測とその検証」へ置き換えたものである。

---

## 第1条：ミッション

毎日、世界のマクロ経済状態をスナップショットとして保存し、
**次回の重要経済指標（CPI / Core CPI / PCE / NFP 等）が上振れするか下振れするかを
判断できる状態**を作ること。そしてその判断が当たっていたのかを、
**半年後・一年後に統計的に検証できる状態**に保つこと。

対象マーケットは Gold（XAUUSD）と USDJPY の2つ。

MIOSは「価格予想AI」ではない。**マクロ経済のリサーチ基盤（Research Infrastructure）**である。
そして「ニュースを要約するAI」でもない。要約は手段であって成果物ではない。

---

## 第2条：優先順位

```
Data Quality > Reproducibility > Validation > Simplicity > Feature Count
```

**機能を増やすことを成功と定義しない。** 成功の定義はただ一つ：

> 半年後に「このシステムはCPI/NFP予測に本当に役立っているのか？」を
> 統計的に検証できる状態にあること。

この問いに答えられない機能は、どれだけ精巧でも価値がゼロである。

---

## 第3条：パイプライン

すべての処理は以下の順序を厳守する。下流は上流の成果物のみを入力にできる。

```
Raw Data              生データ。取得したまま永久保存
  ↓
Normalized Data       型付き・単位付きの正規化値
  ↓
Historical Time Series vintage付きの時系列（当時の値と現在の値を区別）
  ↓
Market Expectations   コンセンサス予想・市場織り込み
  ↓
Institutional Forecasts 機関投資家予測（値そのものより「変化」）
  ↓
News / Events         影響のあるニュースのみ
  ↓
Macro Analysis        マクロ次元スコア
  ↓
CPI / NFP Forecast    自システムの予測（毎日保存・上書き禁止）
  ↓
Cross Asset Analysis  金利・実質金利・ドル・リスクの接続
  ↓
Gold / USDJPY Interpretation
  ↓
Daily Markdown Report
```

予測が「雰囲気」から生成されることを、構造的に不可能にする。

---

## 第4条：事実主義

1. **一次情報 ＞ 二次配信 ＞ 報道 ＞ 解説** の優先順位を厳守する（Tier 1〜4）。
   Tier 3/4 の報道が伝える数値が、Tier 1 の公式発表を上書きすることは決してない。
2. すべての主張は次の3分類のいずれかのラベルを必ず持つ：
   - `FACT`：登録済みソースから取得した実測値（証拠ID必須）
   - `REPORTED`：報道されているが一次確認できていない（出典必須）
   - `INFERENCE`：システムによる推論（推論根拠の明示必須）
3. **数値を捏造しない。** APIが取得できない場合、推測値で埋めない。
4. **欠損は必ず明示する。** 沈黙は禁止。取得失敗を成功として扱わない。

---

## 第5条：LLMの役割は限定される

LLMがしてよいこと：

- ニュースの分類
- テキストの要約
- 因果関係の整理
- 公開文書からの機関投資家予測の抽出
- 相反するシグナルの整理
- レポートの文章生成

**LLMがしてはいけないこと：数値を生成すること。**

数値は原則として API / データベース / 公式発表から取得した値のみを使う。
LLMが作った数値を事実として保存してはならない。抽出した数値には必ず出典URLを添える。

---

## 第6条：Vintage と Look-ahead Bias の構造的排除

1. 経済指標は改定される。**「現在の最新値」と「当時市場が知っていた値」を必ず区別する。**
2. すべての観測値は `observation_date`（参照期間）、`release_date`（発表日）、
   `vintage_at`（その値が有効になった時刻）を持つ。
3. **検証期間より後に発生した情報を使ってはならない。** バックテストのAPIは
   `as_of` を必須引数とし、デフォルト値を持たない。
4. 予測値は**上書き禁止**。毎日の予測をすべて保存し、
   「CPI発表10日前の予測はいくつだったか」を完全に再現できるようにする。

この条文が破られた瞬間、第2条の「成功の定義」は達成不可能になる。

---

## 第7条：計測なくして改善なし

1. すべての予測は保存し、実績発表後に自動採点する。
2. 採点は **MAE / RMSE / 方向的中率 / 上振れ下振れ的中率 / キャリブレーション** で行う。
3. 比較対象を必ず併記する：**コンセンサス予想 / ナイーブ予測（前月と同じ）/ 直近平均**。
   コンセンサスに勝てない予測は、存在しないのと同じである。
4. **採点されない予測機能はリリースしない。**
5. 結果とプロセスを分離して評価する。正しい確率判断でも外れる側は起きる。

---

## 第8条：5年間保守できる設計

1. **運用者は一人**である前提で設計する。一人で理解・修理・拡張できない技術は採用しない。
2. 依存は最小限に。新しいライブラリを増やす前に、既存の依存で実現できないか必ず確認する。
   採用理由は必ずADRとして記録する。
3. **データは資産、コードは消耗品。** 生データを何よりも守る。
   コードは全部書き直せても、生データが無事なら再建できる。逆は不可能。
4. すべての外部データソースは**必ず死ぬ**（API廃止・仕様変更・値上げ）前提で、
   ソースを差し替え可能な抽象化層を置く。
5. LLMモデルは**必ず世代交代する**前提で、プロンプト・モデル選択を設定ファイルに外出しする。

---

## 第9条：不要なものを積極的に削る

**「残すこと」を正当化するのではなく、なぜ残す必要があるのかを説明できないものは削除する。**

削除対象の典型：

- 実質的に使われていない抽象化
- 将来のためだけに存在する未使用コード
- 検証できないヒューリスティック
- 根拠が追跡できないスコア
- 実データが存在しないプレースホルダ
- 同じデータを複数の経路が取得する構造
- 重複ドキュメント

**「将来使うかもしれない」は残す理由にならない。** 必要になった時に、
その時の要求に合わせて書けばよい。git 履歴が消えるわけではない。

ただし **実測データ・過去予測・過去価格・過去ニュース・過去分析結果は削除しない。**
削除する場合は「何を・なぜ・復元可能か」を `docs/DELETION_LOG.md` に必ず記録する。

## 第10条：スコープ

### やること

- 米国・日本の主要経済指標の継続的な取得と vintage 付き保存
- 金利（UST / JGB / 実質金利 / BEI）・為替・コモディティの日次取得
- 経済指標カレンダーと Actual / Forecast / Previous / Revision / Surprise の管理
- 公開情報からの機関投資家予測の収集（**値の変化**を重視）
- Gold / USDJPY に影響するニュースの分類と保存
- 次回 CPI / NFP の予測と、その予測精度の長期検証
- 日次 Markdown レポートの生成（前日差分を必ず含む）

### やらないこと（Non-Goals）

- 発注・自動売買 — MIOSは注文を出さない
- 売買助言（BUY / SELL / 建玉サイズ） — 予測と解釈までが範囲
- 高頻度・日中足の分析 — 時間軸は「日〜週〜月」
- 有料データの無断取得 — 公開情報のみを対象とする
- 万人向けサービス化 — オーナー一人のためのシステム

## 第11条：改正手続き

1. 本憲法の改正はオーナーの明示的承認によってのみ行う。
2. 改正履歴は本書末尾に追記する。
3. 下位設計書が本書と矛盾した場合、本書が優先する。
4. 設計を変更した場合は、その理由を必ず記録する（ADR）。
   **ドキュメントと実装が矛盾した状態を放置しない。**

## 付録：用語定義

| 用語 | 定義 |
|---|---|
| Series | 継続的に発表される一つの時系列（US CPI YoY、JGB 10Y 等） |
| Observation | ある参照期間の観測値。`observation_date` / `release_date` / `vintage_at` を持つ |
| Vintage | ある時点で有効だった値。改定があれば同じ参照期間に複数の vintage が並ぶ |
| Release | 指標の一回の発表。actual / forecast / previous / revised_previous / surprise を持つ |
| Surprise | `actual − forecast`。標準化した `standardized_surprise` も保存する |
| Prediction | MIOS 自身の予測。作成日（`predicted_at`）ごとに保存し、上書きしない |
| Consensus | 市場のコンセンサス予想。MIOS の予測が超えるべきベンチマーク |
| As-of | 「その時点で知り得た情報だけ」を再現するための時刻フィルタ |
| Source Tier | ソースの信頼度（1=公的機関、2=データ配信、3=大手報道、4=その他） |
