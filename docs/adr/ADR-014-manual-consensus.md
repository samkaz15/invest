# ADR-014: コンセンサス予想はスクレイピングせず、手入力で取り込む

- 状態：採択（2026-09-14、オーナー要望を受けて）
- 文脈：オーナーから外為どっとコムの経済カレンダー
  （`https://www.gaikaex.com/gaikaex/mark/calendar/`）からデータを引けないか、
  および Bloomberg 日本版を巡回してニュースを拾えないかという打診があった。

  ADR-012 が記録した通り、**NFP と失業率の月次コンセンサスは MIOS が唯一
  ベンチマークを持てていないデータ**である。ブローカーのカレンダーには
  まさにその「予想」列がある。

## 決定

**自動取得しない。** 代わりに `input/consensus.csv` を人が手で埋め、
`mios consensus` が `external_forecasts` に取り込む。

保存規約は Cleveland Fed の nowcast とまったく同じ：追記のみ、vintage 付き、
出典URL必須、値が変わった時だけ行が増える。

## 理由

1. **予想値はライセンスデータである可能性が極めて高い。** ブローカーのカレンダーの
   予想値は自社調査ではなく、データベンダーから配信を受けているのが通例である。
   自動取得して**公開リポジトリにコミットすることは再配布**にあたる。
   個々の数値そのものに著作権は及ばなくても、体系的な収集と再配布は別の問題である。
2. **人が自分の目で読んで書き写すのは、そのサイトの本来の使い方である。**
   月に数件の数字を自分の研究のために書き留めることと、カレンダー全体を
   機械的に取得することは、規模も性質も違う。
3. **技術的にも脆い。** ブローカーのカレンダーは JS レンダリングのことが多く、
   headless ブラウザが必要になる。GitHub Actions の日次実行に Playwright を
   持ち込むのは重く、サイトの改修のたびに壊れる。憲法第8条の依存最小化にも反する。

## Bloomberg について

`https://www.bloomberg.com/jp` の巡回も行わない。理由は2つあり、重さが違う。

- Bloomberg は公開 RSS を提供していない（主要フィードは以前に廃止された）。
  つまり**配信元が意図した機械可読な経路が存在しない**。
- サイトを直接取得することは規約に反し、bot 対策でも阻まれる。

一次情報は Fed / BOJ / BLS の公式 RSS（Tier 1）で代替し、報道は
FT / CNBC / 産経（Tier 3）で拾う。Bloomberg の強みは速報性と端末であり、
無料の Web コンテンツではない。

## 単位変換をコードに置いた理由

カレンダーが表示する3つの数字は、似て見えて別物である。

| 表示 | 意味 | MIOS に入る値 |
|---|---|---|
| `+0.3%` | 前月比の変化率 | `0.003` |
| `+17.5万人` | 水準の変化（千人単位） | `175` |
| `4.3%` | **水準**（変化ではない） | `4.3 − 前月の値` |

3番目が危険である。失業率は水準で報じられるが MIOS は変化を予測するので、
`4.3` をそのまま保存すると「コンセンサスは +4.3%ポイント」という、
丸め誤差ではなく**二桁違う**数字が入る。しかも誤りの向きが
「人間の予測家が壊滅的に下手で、MIOS が優秀に見える」方向である。

だから変換は CSV の列に掛け算を書くのではなくコードに置き、
対象の transform と unit が食い違う行は**変換せずエラーにする**。推測しない。

## トレードオフ

- 手入力の手間が発生する。月に数行なので許容範囲と判断した。
- Tier 3 として保存する。単独で数値の根拠にはしない（憲法第4条）。
- **1行でも不正ならファイル全体を取り込まない。** 黙って行を捨てるファイルは、
  読み込めないファイルより悪い —— 記録されたと思い込んだまま、
  半年後に比較に穴が空いていることに気づくことになる。
