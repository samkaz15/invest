# ADR-015: 収集対象を米国の数値データに絞る

- 状態：採択（2026-09-16、オーナー判断）
- 文脈：初回の `mios verify-sources`（2026-09-14、実プロバイダ接続）が、
  難所がどこにあるかを数字で示した。

  | 区分 | ソース | 結果 |
  |---|---:|---|
  | FRED / ALFRED / Treasury / Twelve Data | 46 | **全成功** |
  | 日本 MOF（JGB） | 1 | 失敗（文字コード） |
  | ニュース（RSS） | 5 | 失敗2件（産経404・BLS403） |
  | 機関予測（Cleveland Fed） | 1 | 失敗（URL 404） |
  | 手入力コンセンサス | 1 | — |

  **経済指標のソース47個中46個が初回で成功した。** 失敗は指標の周辺 ——
  日本の統計、報道、コンセンサス予想 —— に集中していた。

## 決定

**米国の数値データだけを収集する。** 以下をコードごと削除する。

| 削除 | 理由 |
|---|---|
| 日本 MOF（JGB 5系列）と `mof_jgb_csv` parser | 機関ごとの個別対応が必要で、収集の難所がここに集中する |
| ニュース RSS 5媒体、`ingestion/adapters/rss.py`、`extraction/` | 公開フィードを出す媒体が減り続けている。分類・要約も未実装のまま |
| 機関予測（Cleveland Fed）、`prediction/external.py`、`validation/benchmark.py` | URL が確認できず、無料で機械可読な代替も存在しない |
| 手入力コンセンサス、`prediction/manual.py`、`input/` | 手入力の運用負荷に見合わないと判断 |

残すのは **FRED（38）・ALFRED（5）・US Treasury カーブ（1）・Twelve Data（2）**、
合計46ソース・48系列。すべて初回検証で成功が確認されている。

## 連鎖して消えたもの

削除後に到達不能になったモジュールを機械的に洗い出した結果、
**ニュース以外にも死んでいたコードが見つかった。**

| 削除 | 状態 |
|---|---|
| `src/mios/knowledge/`（6モジュール） | Event Store / Timeline / Entity。**テストからしか参照されていなかった** |
| `src/mios/scoring/` | 参照ゼロ |
| `src/mios/analysis/stats.py` | 参照ゼロ |

`knowledge/` と `scoring/` は Phase 2 の監査で「資産非依存だから残す」と判断したものだが、
**その後一度も使われなかった。** 指示書 §26 の「いつか使うかもしれないからと残さない」に
真正面から違反していたのは、他でもないこの判断である。Phase 6 の前提で残し、
Phase 6 が無くなった時点で根拠も消えた。

## 失うもの（明示する）

1. **「市場がすでに知っていたことより良かったか」に答えられない。**
   ADR-012 が本当の問いと呼んだ比較が消える。残るのはナイーブ基準との比較だけで、
   これは低いハードルである。skill が正でも、主張は弱い。
2. **USDJPY の見方が米国側だけになる。** 金利差の日本側の脚が無い。
   日銀の政策変更は、それが米国側の系列に波及するまで見えない。
   `config/analysis.yaml` の `usdjpy_bias` が blind_spots として毎日明示する。
3. **ニュースが一切入らない。** 金やドル円を動かした出来事があっても、
   系列の数字に現れるまでレポートには何も出ない。

これらは日次レポートの「このレポートが見ていないもの」節に毎回印字される。
**書かれていない欠落は「無かった」と読まれる**ため、対象外にしたことと
未実装であることを、読み手が区別できる形で残す。

## 残したもの

- `external_forecasts` など使われなくなったテーブル：
  **適用済みマイグレーションは編集しない**（後方互換原則、DELETION_LOG 参照）。
  参照を止めるだけにする。`releases.forecast` は恒久的に NULL になり、
  生成列の `surprise` も NULL のままになる。
- 発表カレンダー（`src_fred_release_dates`）：FRED のソースであり、初回検証で成功済み。
- スプレッドシート出力（ADR-013）：`news.csv` だけ落ちて6枚になる。

## 設定読み込みに追加した検査

次元を消したとき、それを参照する view のリンクが宙に浮く。
**これは例外を出さない** —— view はその次元を「欠損」として 0 点で扱い、
少しだけ確信度の低い自分自身として動き続ける。永久に。

BOJ 次元の削除がまさにこれを起こす変更だったので、
`config/loader.py` が読み込み時に弾くようにした。
