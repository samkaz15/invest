# ADR-013: スプレッドシートは CSV 出力とし、DB を正とする

- 状態：採択（2026-09-14、オーナー要望）
- 文脈：オーナーの実際の使い方は「発表された数字をスプレッドシートに貯めて知見を書き足していく」。
  一方 MIOS の中核は「過去の予測・観測値を書き換えられないこと」（憲法第6条4項）である。
  この2つは放っておくと衝突する。

## 決定

**PostgreSQL を正とし、スプレッドシートはその出力とする。**
`mios export` が `exports/*.csv` を毎回丸ごと書き直し、日次ワークフローがコミットする。

| ファイル | 中身 |
|---|---|
| `releases.csv` | **MIOS が観測した発表**。actual / 前月比 / 事前予想 / サプライズ / previous / revised_previous / 改定の有無 |
| `history.csv` | 全系列の値の履歴と前期比。バックフィル分を含む |
| `calendar.csv` | これからの発表予定（時刻の確度つき） |
| `forecasts.csv` | 予測の全 vintage と採点結果 |
| `accuracy.csv` | 採点済み予測の誤差 |
| `series.csv` | 系列台帳と取得状況 |
| `news.csv` | 収集した見出しと Tier |

## 理由

1. **手で編集できる場所を「正」にしない。** 人が書き込めるシートは、履歴を書き換えられる
   シートである。「発表10日前に何と言っていたか」が静かに消えることを、この設計は許さない。
   出力を毎回作り直すので、シートを壊しても真実は失われず、横に書いた知見のメモが
   データと混ざることもない。
2. **依存も認証情報も増えない。** 憲法第8条は依存追加に ADR を要求する。
   `openpyxl` は書式と引き換えに依存を1つ、Google Sheets API は加えて
   サービスアカウントと secret を要求する。コミット済み CSV は Excel で直接開け、
   かつ Google スプレッドシートから
   `=IMPORTDATA("https://raw.githubusercontent.com/samkaz15/invest/<branch>/exports/releases.csv")`
   で**自動更新される**。同じ機能をコストゼロで得られる。
3. **BOM を付ける。** Windows の Excel は BOM なし UTF-8 を Shift-JIS と誤認し、
   日本語の列名が文字化けする。Google スプレッドシートは BOM を無視する。

## トレードオフ

- 書式・複数シート・色分けはできない。必要になったら `openpyxl` を足す ADR を書く。
- **派生値は出力時に計算し、保存し直さない。** 前月比を別テーブルに持つと真実が2つになり、
  いずれ食い違う。`history.csv` と `releases.csv` の前月比が一致することはテストで確認している。
- CSV がリポジトリに増え続ける。毎回上書きなので行数は増えるがファイル数は増えない。

## 関連する設計判断：何を「発表」と呼ぶか

`releases.csv` には**バックフィルで入った過去の値を含めない**。
初回収集で18か月分が一度に入っても、MIOS はそれらが「いつ発表されたか」を知らない。
記録すればダウンロード時刻が発表時刻として残り、**誰も announce していない発表日時**を
主張することになる。

判定規則は単純で、特別扱いを必要としない：**その値が入る直前に、前期の値が
すでに保存されていたか**。保存されていれば MIOS はその系列を見張っていたのであり、
これは観測された発表である。そうでなければバックフィルである。
ALFRED から真の vintage を引いている系列は各 vintage が別々に入るので、
この規則だけで自動的に「発表」として認められる。

バックフィル分は捨てず、`history.csv` に**履歴として**出力する。
発表ではないというだけで、数字は数字である。
