# ADR-012: 精度の判定基準に「機関予測との比較」を加える

- 状態：採択（2026-09-12）
- 文脈：Phase 5〜9 で MIOS は自分の予測をナイーブ基準（直近変化の移動平均）に対して
  採点できるようになった。しかしナイーブ基準に勝つのは低いハードルである。
  CONSTITUTION.md 第2条が定義する成功 —— 「このシステムは CPI/NFP 予測に本当に
  役立っているのか」 —— は、**すでに無料で公開されていた数字に勝てたか**でしか
  判定できない。

## 決定

外部機関の予測を `external_forecasts` に vintage 付きで保存し、
MIOS 自身の予測とまったく同じ条件で採点する（`external_forecast_errors`）。

「まったく同じ条件」とは具体的に3つ：

1. **同じ actual** —— 対象期間の初回発表値。改定後の値ではない。
2. **同じナイーブ基準** —— `prediction.features.changes_of` + `trailing_mean` で、
   その予測自身の vintage 時点で再計算する。MIOS 側がその日たまたま保存していた
   baseline を流用しない。
3. **同じ情報量** —— 突き合わせるのは、MIOS の予測の as-of 時点で**知り得た**
   相手の最新予測だけ。後から公表された予測とは比較しない。

3が最も重要である。30日前の MIOS 予測を発表当日の nowcast と比べれば、
どちらに有利に転んでも、それは2つの別々の問いの答えを並べただけになる。

## 一次ベンチマーク：Cleveland Fed inflation nowcast

Tier 1（連邦準備銀行）、無料、機械可読、月次 CPI・コア CPI を対象期間そのもので予測。
MIOS が予測している当の数字を予測している唯一の無料ソースである。
ほぼ毎日更新されるため、各取得は新しい予測 vintage として保存される（上書きしない）。

## 雇用統計はベンチマークできない

NFP と失業率の月次コンセンサス（Bloomberg / Reuters のエコノミスト調査）は有料であり、
中央銀行は「その月の発表値」の予測を公表していない。
FOMC の SEP と Philadelphia Fed の SPF は失業率を扱うが、四半期・Q4/Q4 の見通しであって
「8月の雇用統計」の予測ではない。別の問いの答えを流用して比較したことにするのは、
数字を捏造するのと同じ種類の誤りである。

したがって `config/external.yaml` の `uncovered` にこの2つを明示的に列挙し、
スキーマは空リストを拒否する。`mios accuracy` と日次レポートは、
ベンチマークできない対象を**毎回名指しで表示する**。

**帰結：MIOS の労働市場側の skill は、CPI 側の skill より弱い主張である。**
比較対象がナイーブ基準しかないためで、これは実装の不足ではなく、
無料で入手できるデータの限界である。

## トレードオフ

- 比較可能な対象が4つ中2つに減る。しかし「2つしか比較できない」と明示することは、
  4つとも比較できたふりをするより正確である。
- 相手の予測も毎日保存するため行数は増える。値が変わった時だけ書くので、
  再公表だけで行が増えることはない（observations と同じ規律）。
- Cleveland Fed の URL・列名はネットワーク非到達の環境で書かれており**未検証**
  （`docs/ARCHITECTURE.md §6 A-3`）。`mios verify-sources` が parse まで検査し、
  列名が違えば**実在する列名を列挙して**失敗する。誤った設定が
  「今日は予測が無かった」として静かに通ることはない。
