# DATA_SOURCE_REGISTRY.md
# BIOS データソース台帳（追加提案）

> **本書はオーナー指示の5文書に含まれないが追加提案するもの。** 理由：事実主義（憲法第4条）は「どの情報源をどれだけ信頼するか」の明文化なしには実行できない。またソースは必ず死ぬ（憲法第8条4項）ため、差し替え判断の台帳が必要。
> 本書の実体は設定ファイル（`sources.yaml`）としてコード外管理し、本書はその設計と初期値を定める。

---

## 1. 信頼Tier制度

| Tier | 定義 | 例 | 扱い |
|---|---|---|---|
| **1** | 一次情報（当事者の公式発表・原文書・チェーン上の事実） | SEC文書 / 裁判所記録 / 企業IR・8-K / 中央銀行発表 / オンチェーンデータそのもの | 単独で`FACT`認定可 |
| **2** | 準一次（一次データの機械的集計・配信） | ETFフロー集計 / 取引所公式API / オンチェーン分析プロバイダの生指標 | 単独で`FACT`認定可（集計手法の注記つき） |
| **3** | 大手報道（一次取材あり） | Bloomberg / Reuters / WSJ / 日経 | `REPORTED`。Tier1-2で裏取りできたら`FACT`昇格 |
| **4** | 業界メディア・二次報道 | CoinDesk / The Block 等 | `REPORTED`。速報の入口として有用、単独でFACT不可 |
| **5** | SNS・個人・匿名情報 | X上のアナリスト / オンチェーン探偵 | `UNVERIFIED`。**Event化にはTier3以上の裏付け必須**。ただし発覚の早さで価値あり（「検知はTier5、確定はTier1-3」の役割分担） |

**規律**：magnitude 4以上（市場を大きく動かす）のEventは、Tier1-2の証拠を最低1件持つまで`confidence: reported`から昇格できない。

## 2. ソース台帳スキーマ

```yaml
- source_id: src_sec_press
  name: SEC Press Releases
  tier: 1
  domains: [regulation, etf]        # タクソノミ第1階層との対応
  method: rss                        # rss | api | scrape | manual
  cadence: 15min
  cost_monthly_usd: 0
  status: active                     # active | degraded | dead
  fallbacks: [src_sec_edgar]         # このソースが死んだ時の代替
  notes: 一次。ETF・執行関連の起点
```

## 3. 初期ソースセット（カテゴリ別・費用意識つき）

Phase 1は**無料〜低額ソースのみ**で開始し、見逃し検知（EVALUATION §6）が示した穴に応じて有料ソースを追加する（最初から高額データを買わない）。

| カテゴリ | 初期ソース候補 | Tier | 費用感 |
|---|---|---|---|
| 規制・裁判 | SEC/CFTC/DOJ発表、裁判所記録（PACER）、金融庁 | 1 | 無料〜微少 |
| ETFフロー | 発行体開示、Farside等の集計サイト | 1-2 | 無料 |
| オンチェーン | 公開ノード/エクスプローラ、無料枠のオンチェーン指標（exchange netflow, MVRV, SOPR）、政府・Mt.Gox等の既知ウォレット監視 | 1-2 | 無料〜$100/月 |
| 市場・デリバティブ | 大手取引所公開API（価格/OI/Funding/清算）、オプションデータ | 2 | 無料 |
| 企業・政府保有 | 企業IR/8-K、保有集計サイト、政府発表 | 1-2 | 無料 |
| マイナー | ハッシュレート公開データ、上場マイナーIR | 1-2 | 無料 |
| マクロ | FRED、各国中銀、経済指標カレンダー | 1 | 無料 |
| 報道 | 大手金融メディアRSS、暗号資産専門メディアRSS | 3-4 | 無料〜購読費 |
| 早期検知 | X上の定評あるアカウント群（ホワイトリスト制） | 5 | 無料/API費 |

**将来の有料候補**（見逃しが証明されたら）：Glassnode/CryptoQuant上位プラン、Arkham、ニュースAPI、オプション分析。

## 4. 運用ルール

1. **ソース追加の手続き**：見逃し検知レポートまたはオーナー要望 → Tier査定 → `sources.yaml`へ追記 → アダプタ実装。台帳にないソースからの取り込みは禁止（出所不明データの混入防止）。
2. **死活監視**：各ソースの最終取得成功時刻を監視、24時間途絶で`degraded`、アラート。ブリーフィングに欠損として明示。
3. **四半期棚卸し**：費用対効果（そのソース由来のEventが判断に使われた回数）でランキングし、死枝を剪定。
4. **アーカイブ**：Tier1証拠のURLは取得時にアーカイブ保存（リンク切れで証拠チェーンが壊れることを防ぐ）。
